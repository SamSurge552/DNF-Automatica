## 1. 核心想法

过图不是回放死脚本，也不是行为克隆。现行是**模块化 agent**：YOLO+OCR 感知 → FSM 决策 → 快捷栏执行。开打先在回放里把**意图**跑对（蓝字），发键另等点头。

开打的数据从「人在录像里怎么按」抽成过图技能特征，再按房间用，而不是全图共用一套。

| 点 | 现行约定 |
|----|----------|
| 技能顺序 | **每个房间自己的**真释放次数序（高到低）。没有该房就空，不用全局一条、也不用 `room=-1` 兜底 |
| CD | 放过就倒计时，**跨房间 / WAIT / 回城都保持**，只在该图的【重置】点清空 |
| 重置点 | 录像里某技能间隔短于键位表 CD → 记在 raw BOSS 1→0（本房见过 boss）之后进入的**第一个相似房间**。发现后给该图加地图特征【重置】；回放可删。开打只在有【重置】时才在相似房清 CD |
| 杀怪 | 效率只看 MON（`killed_mon / 起始 mon`），报告写 **杀MON效率**，不要和 BOSS 混 |
| 假释放 | 起始有 MON 且杀MON效率 < **F%**（默认 50）→ 只标 `fake`，不进次数 / 范围 / 序列。无 MON（BOSS 房）不标。F 是 GUI 参数 |

相似房间：开打出现时 MON+BOSS 群中心 + 数量，差不超过 **S%** 则同一房号。回城/等待清空房间指纹，**不清 CD**。

连续释放（特征表勾选）：该槽 CD 按 **270 秒**，不再「不计 CD / 强制垫底」。

## 2. 演进逻辑 / 技术路线

### 2.1 已走过的路（本会话覆盖的旧约定）

1. **房间号**：离开前进 +1 → 开打出现时相似匹配（S%）。未回城连刷可对上。  
2. **技能顺序**：全图一条频率顺序 → **按房间次数序**（假释放不计入）。  
3. **CD**：WAIT/回城清空；或「相似房一律清」→ **保持到【重置】**；仅地图有【重置】且 BOSS1→0 后第一个相似房间才清。  
4. **效率**：曾写「效率均」→ 实际一直是 MON 减少量，报告改名 **杀MON效率**。  
5. **错按**：录像黄字有、实际没打出 → 用杀MON效率 < F% 当假释放代理，写入文件只做标注。  
6. **开打执行**：txt 六步意图已进 `fsm_core`（`CAST` / 接近），回放蓝字可见，**不发键**。

### 2.2 当前主链路（应保持）

```
录像 jsonl（t_ns 原样）
    → fsm_replay：绿=状态 / 蓝=意图 / 黄=人按了什么
    → 提取：开打 ∩ 黄字技能段 → skill_features/<图>/<角色>.json
```

可调值都在回放主面板（M/L/G/X/A/Y/S/E/**F**），与 FSM测试共用 `_fsm_replay_ui.json`。

### 2.3 关键约定速查

- 核心一份：`fsm_core.py`。回放 `fsm_replay.py`，实机 `status_analysis_module.py`。  
- 特征：`skill_features/<地下城>/<角色>.json`（`sequences` / `casts[].fake` / `cd_resets` / `map_tags`）。
