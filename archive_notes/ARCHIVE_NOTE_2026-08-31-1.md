## 1. 核心想法

过图模型要学的是「这一眼画面下，人在这段时间里怎么操作」，不是「这一帧有没有收到一次 keydown」。

- **视觉：** YOLO 结构化特征（`player_xy / mon / loot / gate / boss`），不存 PNG。坐标相对**整窗**。
- **键盘：** 磁盘只存微秒级 **press/release 事件**；训练时在每一视觉区间里统计成两个连续量：
  - **`count`**：区间内真实按下沿次数（去 Windows 连发后的「点了几下」）
  - **`held_frac`**：区间内按住时长 / 真实 dt（「死死按住跑」≈1.0，「擦边」≈0.2）
- **时间：** 一行 YOLO 对齐「上一帧 → 本帧」整段键盘，而不是 0/1 多热，也不是「有事件的那一帧才有标签」。
- **进图：** OCR 只认图名（可裁右上角省算力）；角色名 GUI 下拉。一图一段开停录。

一句话：事件流保细节，区间编码当标签，惯性只在导出时填玩家坐标。

## 2. 演进逻辑 / 技术路线

### 采集侧（已落地）

1. 进图才录、回城停录；点开始就录 / 城镇数据已否决。
2. 角色 OCR 去掉 → `character_names_custom.txt` 下拉（与 YOLO 版本同一交互）。
3. 全屏照截；OCR 只跑框选相对客户区（进图图名）；YOLO **不受裁剪干扰**。
4. 仅截图曾被「录制不落盘」盖掉 → 已改为按间隔写 `images/`。
5. 管理员才能钩到 DNF 按键；GUI「以管理员身份重启」+ PATH 快照（UAC 会丢 CUDA PATH）。
6. 截图 ImageGrab ~40ms 且帧戳偏晚 → **dxcam**（失败回退 Pillow）；OCR/录制共用 `ScreenCaptureModule`（加锁）。
7. YOLO：默认 **v7**；加载后 GPU warmup；固定 `imgsz=640, device=0` 复用 predictor。letterbox 仍走 Ultralytics，**不在 CPU 上擅自拉成 640×640**（会破坏与训练一致的框映射）。

### 标签侧（约定已写进 TRAIN_ALIGN，导出脚本未写）

| 阶段 | 做法 | 为何被否 / 被替 |
|------|------|------------------|
| 按事件当 y | 两秒长按只有 1 帧有标签 | 模型学「别动」 |
| 连发 press 当决策 | 一次按住变成几十次点按 | 学「狂点右」 |
| 每帧 GetAsyncKeyState | 只要瞬间状态 | 两帧之间的点按丢失 |
| 0/1 多热 / `held_any` | 开或关 | 连点、擦边、长按糊成同一个 1 |
| **事件重建 hold + 区间 count/held_frac** | 当前主方案 | 一行视觉吃掉整段 dt 的键细节 |
| 录制端把 `player_xy` null 盖掉 | 看似省事 | 丢掉漏检信息；惯性放**导出** |

`count` 只计本区间新按下沿；长按延续只体现在 `held_frac`。dt 用相邻帧真实时间差，不写死 200ms。
