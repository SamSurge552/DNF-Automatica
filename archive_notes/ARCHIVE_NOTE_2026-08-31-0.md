## 1. 核心想法

用**人过图**当老师，训**按地下城 × 角色**的过图小模型，再驱动自动化——而不是回放死脚本。

具体拆成两层感知 + 一层策略：

| 层 | 作用 |
|----|------|
| OCR | 只负责「在不在图 / 哪张图」；进图开录、回城收尾（一图一段） |
| YOLO（V6） | 把整窗压成结构化状态：`player_xy / mon / loot / gate / boss` |
| 过图小模型（待训） | 输入上述状态（及对齐后的键标签），输出操作；自动化挂这里 |

监督信号是 **YOLO 特征 + 键盘事件流**，**不存 PNG**。  
旧 `scripts/*.script` 路线已废弃；数据只进 `recordings/`。

录制与组训练集要分开想：

- **磁盘 jsonl**：尽量原样（可有 `player_xy: null`、可有键盘 auto-repeat press）
- **导出训练集**：再做 player 惯性、按键 `count` / `held_frac`；不要改原始文件

## 2. 演进逻辑 / 技术路线

### 2.1 已走过的路

1. **整窗截图 + OCR** 判城镇/地下城/角色 → GUI 控制面板  
2. **检测**：Paddle → RapidOCR；检测模型 YOLO26n 自训至 **v6**（`boss/gate/loot/mon/player`）  
3. **CUDA 共存**：必须先 Torch cuDNN warmup，再 ORT CUDA13 预加载（否则加载失败或置信度塌掉）  
4. **录制重构**：双线程解耦（键盘 / 截图+推理）+ 写盘队列；绝对时间戳 `t_ns`  
5. **产品边界修正**：点开始不录、回城必停录；自动化改为小模型占位，删掉 script 体系  
6. **训练对齐约定**（见 `TRAIN_ALIGN.md`）：帧戳偏晚 ~40ms、player 惯性仅导出时做、键标签用区间 `count+held_frac` 而非 0/1 多热  

### 2.2 当前主链路（应保持）

```
对齐窗口 → 开始（预加载 YOLO）→ OCR 循环
    ├─ 进图 + 录制 → recordings/<图>/<时段>[_角色]/ meta + keys.jsonl + frames.jsonl
    ├─ 进图 + 自动化 → 占位日志（模型未挂）
    └─ 回城 / 换图 / 停止 → 收尾本段
导出训练集（未写脚本）：player forward-fill + 键 hold 重建 → count / held_frac
过图小模型训练 → 自动化接入
```
